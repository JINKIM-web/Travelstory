# TravelCanvasAI

여행 사진을 올리면 AI가 사진을 분석해 **장면(Scene)** 으로 묶고, 하나의 **여행 이야기(Story)** 와 **스토리 카드**, 그리고 **스토리북**으로 만들어 주는 웹앱 (MVP).

> 사진만 올리면 AI가 지나간 여행을 하나의 이야기로 만들어준다.

- 기획·명세: [SPEC_프로젝트개발명세서.md](SPEC_프로젝트개발명세서.md), [design.md](design.md)
- 개발 계획: [PLAN_프로젝트개발계획.md](PLAN_프로젝트개발계획.md), [PLAN_MVP보강_스토리북.md](PLAN_MVP보강_스토리북.md)

## 주요 기능

| 영역 | 내용 |
|---|---|
| 프로젝트 | 여행 1개 = 프로젝트 1개. 생성·정보 수정·삭제(확인창), 대시보드 필터(전체/스토리 완성/작성 중), 백업(.zip) 저장·불러오기 |
| 사진 | 다중 선택·Drag & Drop, JPG/PNG/WEBP/**HEIC**, EXIF 촬영시각 추출, 원본·썸네일 IndexedDB 저장, 원본 앨범 |
| AI 분석 | 사진별 장면·분위기·설명·중요도(OpenAI 비전). 실패한 사진만 재분석 |
| 씬 빌더 | 촬영 시각·장면 유형으로 자동 그룹화, 제목·키워드 생성, 제목 편집·씬 순서 변경·**사진 드래그 순서 변경**·씬 간 이동·대표 사진 지정 |
| 스토리 | 기억 질문 3개 + 문체 선택(담백/감성/문학) → AI 에세이. 직접 수정, 전체/**챕터별 재생성**, **AI 제목 제안**, **사실 점검** |
| 스토리 카드 | 템플릿 3종, **4:5 / 9:16**, AI 추천 대표 사진, Unsplash 배경(출처 표기), PNG/JPG 저장 |
| **스토리북** | 스토리·씬으로 표지~뒷표지 자동 구성, 페이지 편집, 책 넘겨보기 뷰어, PDF 저장 |

## 화면(라우트)

```
/trips                          대시보드

/trips/:id/photos               원본 앨범 (사진별 AI 분석 보기·수정)
```

## 시작하기

요구 사항: Node.js 20+ (개발은 Node 24에서 진행)

```bash
npm install
cp .env.example .env.local   # 키 입력 (아래 참고)
npm run dev                  # http://localhost:5173
```

> **Windows 주의:** 프로젝트 경로에 `;` 가 들어 있으면 `npm run …` / `npx` 가 동작하지 않습니다.
> 이 경우 `node node_modules/vite/bin/vite.js` 처럼 직접 실행하거나, `;` 없는 경로로 프로젝트를 옮기세요.

### 환경 변수 (`.env.local`)

| 변수 | 설명 |
|---|---|
| `OPENAI_API_KEY` | OpenAI 키. **서버(개발 서버 프록시 / Vercel 함수)에서만** 사용되고 브라우저 번들에 들어가지 않음. 없으면 **데모 모드**(AI 호출 없이 입력값 기반 기본 문구) |
| `VITE_OPENAI_MODEL` | (선택) 모델. 기본 `gpt-4o-mini` |
| `VITE_UNSPLASH_ACCESS_KEY` | Unsplash Access Key. 없으면 배경은 무드 그라데이션만 사용 |

기존의 `VITE_OPENAI_API_KEY` 이름도 호환되지만, `VITE_` 접두사는 개발 모드에서 브라우저에 노출될 수 있으므로 **`OPENAI_API_KEY` 로 바꾸는 것을 권장**합니다. `.env.local` 은 Git에 올라가지 않습니다.

### 스크립트

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 (OpenAI 프록시 포함) |
| `npm run build` | 타입 검사 + 프로덕션 빌드 |
| `npm test` | Vitest (단위·프로젝트 격리 테스트) |
| `npm run export-pdf -- <백업.zip> [out.pdf]` | 백업 안의 스토리북을 PDF 파일로 저장 (개발 서버 실행 중, Chrome/Edge 필요) |

## 구조

```
src/
├── components/   common(ui, Sortable, ScaledPage, Layout, ErrorBoundary) · dashboard · project · photo · story-card · storybook
├── pages/        Dashboard · NewProject(위저드) · ProjectDetail · Story · StoryCard · Storybook · Album
├── services/
│   ├── ai/         client(OpenAI 어댑터) · photoAnalysis · sceneBuilder · storyGenerator
│   ├── storage/    localStorage · indexedDB
│   ├── storybook/  build(자동 구성 규칙)
│   ├── backup/     .zip 백업/복원
│   ├── image/      리사이즈 · EXIF · HEIC 변환 · 카드 내보내기
│   ├── unsplash/   배경 검색
│   └── pipeline.ts AI 4단계(분석→씬→스토리→카드) 실행·상태 저장
├── stores/       Zustand (프로젝트·하위 데이터)
├── types/        데이터 모델 (index.ts, storybook.ts)
└── __tests__/    Vitest
api/openai.ts     Vercel 서버 함수 (OpenAI 프록시)
```

### 데이터 저장

- **LocalStorage:** 프로젝트 메타, 분석, 씬, 스토리, 카드, 스토리북, 기억 답변 (`tc:<projectId>:<part>`)
- **IndexedDB:** 사진 원본·썸네일 (`projectId` 인덱스)
- 모든 데이터는 `projectId` 로 격리되며, 삭제 시 해당 프로젝트의 LocalStorage·IndexedDB 데이터를 모두 지웁니다.
- 브라우저 데이터를 지우면 사라지므로 중요한 여행은 대시보드 카드의 **백업 저장(.zip)** 을 사용하세요.

### AI 호출 구조

```
브라우저 ──POST /api/openai──▶ (개발) Vite 프록시 / (운영) api/openai.ts ──▶ OpenAI
                                    └ 서버 쪽 OPENAI_API_KEY 를 붙임
```

### v0.3.1 — 스토리북 PDF 파일 생성 (2026-10-01)

- **PDF 내보내기 스크립트:** `scripts/export-pdf.mjs` (`puppeteer-core` + 시스템 Chrome/Edge). 백업(.zip)의 스토리북을 인쇄 전용 페이지(`/print-book?src=…`)로 렌더해 PDF 로 저장. 판형(정사각형 600×600px / A5)에 맞는 용지 크기, 배경·웹폰트 포함
- **인쇄용 사진 1600px:** 인쇄·PDF 에는 원본(4000px대) 대신 1600px 사본을 사용 → 17쪽 스토리북이 **139.9MB → 9.7MB**. 브라우저의 "PDF 저장"에도 동일하게 적용
- 사용 예:
  ```bash
  node node_modules/vite/bin/vite.js                       # 개발 서버
  node scripts/export-pdf.mjs sample-backup/2025-02-trip.travelcanvas.zip out/storybook.pdf
  ```

### v0.3.0 — UI 개편 · 로고 · Unsplash 메인 배경 · 스토리북 레이아웃 최적화 (2026-10-01)

**1. UI를 최신 여행 앱 스타일로 개편 (가독성 중심)**
- **로고 아이콘 신규:** 여행 핀 + 풍경 사진 + AI 반짝임을 합친 앱 아이콘(`LogoMark`)과 워드마크(`Logo`). 헤더·푸터·메인 히어로·빈 화면에 사용하고 파비콘(`public/favicon.svg`)과 브라우저 테마색도 추가
- **메인 화면(대시보드):** 전체 폭 히어로(큰 제목·CTA·유리 질감 통계 칩) + 이미지 중심 3열 카드. 카드는 4:3 대표 사진, 상태 뱃지(AI 스토리 완성 / 작성 중), 사진 수, 장소·기간, 핵심 문장, 열기 버튼
- **공통:** 둥근 pill 버튼·큰 터치 영역(최소 40~48px), 입력창·모달·카드 반경/그림자 재정의, 포커스 링 강화, 기본 글자 16px
- **타이포:** UI 제목은 산세리프(Pretendard, 굵게)로 통일해 가독성 향상. 스토리 제목·챕터·인용만 세리프 유지, 스토리 본문은 17px / 행간 1.95
- **색상:** 청보라 배경 → design.md 의 따뜻한 린넨 중립색(`#FAF8F5` 계열)으로 변경, 텍스트 대비 상향
- **프로젝트 상세:** 뒤로가기 링크, 큰 제목과 메타 정보, 아이콘이 있는 탭(스토리 / 카드 / 스토리북 / 앨범, 스크롤 시 상단 고정)
- **모바일:** 떠 있는 둥근 하단 탭바, 390px 전 화면 가로 넘침 없음 확인
- 위저드·씬 카드·스토리·스토리북 편집 패널의 카드 스타일과 제목 크기 통일

**2. 스토리북 생성 시 레이아웃 최적화** (`src/services/storybook/build.ts`)
- **사진 비율 반영:** 가로 사진 2장은 위아래(`stack`), 세로 사진이 섞이면 나란히(`row`). 3장은 중요도가 가장 높은 사진을 히어로로 올리고, 가로 히어로는 위에 넓게(`top`) / 세로 히어로는 왼쪽에 길게(`left`)
- **1장짜리 쪽 방지:** 쪽당 최대 3장을 고르게 분배 (4장 → 2+2, 5장 → 3+2, 6장 → 3+3)
- **사진 선별:** 한 씬 사진이 6장을 넘으면 AI 중요도 상위 6장만 쓰고 촬영 순서는 유지
- **본문 길이 대응:** 본문이 사진과 함께 들어가기엔 길면 "글만 있는 쪽 + 사진 쪽"으로 분리, 글자 크기도 길이에 따라 단계적으로 조정(넘침 방지). 판형별(정사각형/A5)로 글자 수 기준이 다름
- **판형 자동 추천:** 세로 사진이 절반 이상이면 A5 세로, 아니면 정사각형
- 편집 패널에 **배치 방향 선택**(나란히/위아래, 큰 사진 왼쪽/위)과 **"사진 비율에 맞게 자동 배치"** 버튼 추가
- 기존 스토리북은 그대로 유지되며, **"스토리로 다시 구성"** 을 누르면 새 규칙으로 다시 만들어짐(수정 내용은 덮어씀)

**3. Unsplash API 로 메인 화면 배경 구성**
- 메인 히어로 배경을 Unsplash 풍경 사진으로 구성(`fetchHeroBackground`). 검색어 8종을 날짜별로 돌려 쓰며(`HERO_QUERIES`), **하루 1회만 검색하고 localStorage 에 캐시**해 API 호출을 아낌
- 이미지가 완전히 로드된 뒤 부드럽게 나타나며(페이드인), 키가 없거나 실패하면 따뜻한 그라데이션 배경으로 대체
- 가독성을 위한 어두운 오버레이, 촬영자 출처 표기(링크 포함) — Unsplash 가이드라인 준수
- 필요한 설정: `VITE_UNSPLASH_ACCESS_KEY`

**테스트:** 스토리북 레이아웃 규칙 11개 추가 → 총 31개 통과 (`npm test`)

### v0.2.0 — MVP 보강 + 스토리북 (2026-10-01)

**신규: 스토리북**
- 스토리·씬·카드 정보로 책 페이지 자동 구성(표지 → 프롤로그 → 챕터 → 인용 → 에필로그 → 뒷표지). **AI 추가 호출 없음.** 한 씬 사진은 최대 6장(2쪽)
- 챕터 레이아웃 4종(텍스트 / 풀 사진 / 2분할 / 3분할), 테마 3종(Editorial / Film Polaroid / Minimal), 판형 2종(정사각형 600×600 / A5 세로)
- 편집: 쪽 추가·복제·삭제, **드래그로 쪽 순서 변경**, 본문·캡션·제목 수정, 사진 교체·순서 변경
- **책으로 보기** 뷰어: 데스크톱 양면 펼침 / 모바일 한 쪽씩, ←→ 키 지원
- **PDF 저장**(브라우저 인쇄 → PDF로 저장, `@page` 판형 지정), **현재 쪽 PNG 저장**
- 스토리를 다시 생성해도 스토리북은 유지되며, "스토리로 다시 구성"을 눌러야 덮어씀(확인창)
- 신규 파일: `src/types/storybook.ts`, `src/services/storybook/build.ts`, `src/components/storybook/*`, `src/pages/Storybook/`

**AI·스토리 품질**
- 챕터(씬)별 부분 재생성
- 사실 점검: 스토리 문장이 사진 분석·사용자 기억에 근거하는지 AI로 점검해 챕터 아래에 표시
- AI 제목 제안 3개(편집 모드에서 선택)
- 프롬프트 강화: 해당 씬 사진 근거만 사용, 시간대·날씨·행동·음식은 근거가 있을 때만, 생성 temperature 0.5
- 사진별 AI 분석(장면 유형·분위기·설명·중요도·신뢰도)을 앨범에서 확인·수정
- 스토리 화면: 사진 라이트박스, AI 씬 요약 목록(클릭 시 해당 챕터로 이동)

**P1 / 디자인 보강**
- 씬 안 사진 **드래그 순서 변경** (dnd-kit)
- 스토리 카드 **9:16** 비율, AI 추천 대표 사진(중요도 상위 3), 이미지 배경 출처(크레딧) 카드에 표기
- 대시보드 필터 탭(전체 / 스토리 완성 / 작성 중)·최근 수정순 정렬

**안정성·운영**

## 알려진 제한 / 다음 작업

- **PDF:** 인쇄용 렌더(17쪽, 이미지 전부 로드, `@page` 크기)까지 확인했으며, 브라우저 "PDF로 저장" 대화상자를 통한 최종 PDF 결과물은 직접 확인이 필요합니다.
- **HEIC:** 변환 경로는 구현되어 있으나 실제 HEIC 파일로는 아직 시험하지 못했습니다. 변환 시 EXIF 촬영시각은 사라질 수 있습니다(씬은 업로드 순서로 구성).
- **운영 배포:** `api/openai.ts` 는 인증·호출 한도가 없습니다. 공개 서비스 전에 로그인 또는 rate limit 을 추가하세요. Vercel 배포 자체는 아직 하지 않았습니다.
- **AI 품질:** 사진 분석은 비용 절감을 위해 저해상도(low detail)로 요청합니다. 세밀한 정보(간판 글자 등)는 놓칠 수 있고, 사실 점검도 AI 판단이므로 최종 확인은 사용자가 해야 합니다.
- **용량:** 모든 데이터가 브라우저에 저장되므로 사진이 매우 많으면 한도에 닿을 수 있습니다(경고 배너 표시). 클라우드 저장은 P2.
- **MVP 범위 밖(구현 안 함):** 로그인, 클라우드, 공유 URL, GPS 지도, 소셜, AI 영상, 인쇄 주문·결제, 알림, 검색
